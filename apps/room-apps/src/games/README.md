# 纸上游乐场

启用 Mineral 热同步后创建并打开 `games.ui.md`。Obsidian 新建笔记时输入 `games.ui`，让它自动补 `.md`。这是专用游戏文件，服务器会接管正文并生成 TSX / React Router 界面。

## 三种玩法

| 游戏 | Markdown 的作用 | 玩法 |
|---|---|---|
| 矿区排雷 | 6×6 表格棋盘、坐标方括号、行动勾选框 | 8 雷，首步及周围安全，零格连片展开，插旗推理，翻开 28 个安全格获胜 |
| 密码档案 | 输入方括号、历史推理表格 | 4 个不重复数字，8 次机会，反馈位置正确及存在但错位的数量，重复/无效提交不扣机会 |
| 纸页地牢 | 分支行动清单、资源状态、心形血条、共享战报 | 8 页冒险，6 种中途场景加最终关，选择补给/风险/交易/遗物，可喝药、撤退或争取通关 |

编辑输入控件的方括号，然后只勾选一个行动，等服务器更新后再操作。大厅可以继续三种游戏的各自进度；“新一局”仅替换对应游戏。战绩页记录开局、胜利、最高分、累计积分与四项成就。没有实名玩家身份，积分属于本文件的共享游戏桌。

冒险的风险按每局种子和页数确定，重连不能重掷。安全撤退结算金币、遗物、探索和生命；生命归零只结算四分之一金币。不同场景提供有成本且可见的选择，战报保留最近 16 条。游戏不调用模型或索引服务，不需要额外平台绑定。

## 同步与恢复

- 初始按名称注册。初始化后可正常改名为其他 `*.ui.md`，沿用已有 DocumentId 绑定；改成普通 `.md` 后停止。
- 同一文件就是共享游戏桌，所有客户端接力操作同一状态。每个行动带服务器回合号，旧行动、禁用行动和一次勾选多个行动都不会推进游戏。
- 游戏的答案、雷位置和随机种子只在房间私有持久状态中；未结束时不写进 Markdown、公共同步标记或日志。客户端不能靠编辑正文更改答案或战绩。
- Markdown 只保留公开的回合与路由标记，清空/损坏正文会从私有状态恢复。房间驱逐后也继续同局。普通文件备份只有公开画面，不能靠文件副本恢复隐藏答案。
- 复用现有 ScreenPort 条件提交、Yjs 广播、Vault checkpoint 与客户端重连；没有新同步协议、定时动画或持续后台 AI。没人在线时停止运行。
